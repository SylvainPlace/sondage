# Domain docs

Avant toute exploration fonctionnelle, lire :

- `CONTEXT.md` ;
- les ADR pertinents dans `docs/adr/`.

Le dépôt utilise un contexte unique.

Les termes définis dans `CONTEXT.md` doivent être repris dans les specs,
tickets, tests et noms de modules. Les synonymes explicitement déconseillés
doivent être évités.

Toute proposition contredisant un ADR doit signaler le conflit explicitement
au lieu de remplacer silencieusement la décision existante.
